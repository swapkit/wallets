Migrate Ledger connections to the Device Management Kit by default. `@swapkit/wallets` and `@swapkit/sdk` re-export the Ledger wallet, so they carry these changes too.

Browser connections now discover and reuse one WebHID DMK session. Consumers that manage the device lifecycle can pass a caller-owned `dmkSession`; `originToken` authenticates EVM Transaction Checks, and `onDeviceActionState` exposes device prompts to the UI. New exports: `getLedgerDMKSession`, `preloadLedgerDMK`, `disconnectLedgerDMKSession` and the `LedgerDMKSession`, `LedgerDeviceActionState` and `LedgerDeviceActionStateHandler` types.

Breaking changes:

- WebUSB is no longer used. The default connection requires WebHID, so browsers without it (Android Chrome) can no longer connect a Ledger: the connection fails with `wallet_ledger_webhid_not_supported`, and `wallet_ledger_webusb_not_supported` is no longer raised. A Ledger the user already granted to the site reconnects without the device picker; otherwise opening the picker needs a user gesture, so call `preloadLedgerDMK()` ahead of the click to keep the gesture window.
- Device errors are now `SwapKitError`s: `wallet_connection_rejected_by_user`, `wallet_ledger_device_locked`, `wallet_ledger_app_not_open`, `wallet_ledger_connection_error` or `wallet_ledger_transport_error`, with the DMK tag, status word and innermost message in `info`. Code that matched hw-transport's `TransportStatusError` or `statusCode` must switch to `errorKey`. A rejection on the device maps to `wallet_connection_rejected_by_user` on every chain, including NEAR, Sui and Tron signing and the Cosmos and THORChain apps, which reject with 0x6986. Errors from an injected LedgerJS `transport` are passed through unchanged.
- EVM chains require a DMK session; passing a LedgerJS `transport` for them throws `wallet_ledger_invalid_params`. The injected `transport` remains a temporary compatibility path for other chains, cannot be combined with `dmkSession`, and no longer signs Zcash (hw-app-btc picks a pre-Ironwood branch id). Bitcoin `signTransaction` over it returns the finalised transaction from the legacy app, like the other legacy UTXO chains.
- EVM signing opens the Ethereum app for every EVM chain, so it must be installed; another Ethereum-compatible app open on the device is no longer used. On Stax and Flex the signer kit asks the user once, on the device, to opt in to Transaction Checks, whether or not an `originToken` is passed.
- EVM transactions fall back to blind signing on every chain, not only on Arc: when the device rejects the clear-signing metadata, the signer kit signs again without it (after any device error other than the user's refusal), and metadata the Ledger services fail to return is skipped. An outage or a blocked Ledger domain can therefore turn a clear-signed ERC-20 approval into a blind signature on any chain; the device still requires blind signing to be enabled and the user to confirm. `onDeviceActionState` reports the `signer.eth.steps.blindSignTransactionFallback` and `signer.eth.steps.signTypedDataLegacy` steps so a UI can warn about it. EIP-712 signing already fell back to hash-only signing on every chain.
- EVM `signMessage` signs a string as its UTF-8 bytes, as ethers signers do, and a `Uint8Array` as raw bytes. The LedgerJS client hex-decoded string messages, so callers that passed hex text must pass `getBytes(hex)` instead.
- EVM `signTransaction` rejects a transaction whose `chainId` differs from the client's chain with `wallet_ledger_invalid_params` instead of signing it for that chain.
- Legacy Zcash PCZT v4 signing is no longer a supported Ledger path.
- UTXO `transfer` honours `feeOptionKey` and defaults to `FeeOption.Fast`, like the toolbox transfers and the other hardware wallets, instead of always paying the average rate. Swap memos are signed exactly as given: the Bitcoin Cash, Litecoin, Dogecoin, Dash and Zcash transfers no longer shorten them, which dropped the price limit, the affiliate fee or the destination.

EVM, Bitcoin, Cosmos and transparent Zcash signing use the Ledger Device Signer Kits (the Zcash kit is still pre-1.0). THORChain uses its app-v2 protocol in one atomic DMK action, and chains without a signer kit run their existing Ledger app client through an operation-scoped DMK bridge. A default session that was lost (device unplugged, `disconnectLedgerDMKSession()`) is re-established on the next operation instead of failing until the wallet reconnects. The Ledger entry no longer loads any Ledger library eagerly, so `@swapkit/wallet-hardware/ledger`, and through it `@swapkit/wallets/ledger` and `@swapkit/sdk`, can be imported under Node ESM.

EVM message, transaction and full EIP-712 signing use the current signer APIs, sending only the types the primary type references, and an untyped gasPrice-only transaction is signed as legacy, as before. Arc keeps Ledger support: the Ethereum signer kit loads the network certificate and Ledger-signed network descriptor itself, replacing the `PROVIDE_NETWORK_INFORMATION` APDUs added in 4.11.0. The signer kit's blind-signing telemetry, which reports the chain, target address and device model to Ledger on every signature, is disabled, as is its second sign reporter.

Bitcoin requests PSBT signatures from the signer kit and finalises the transaction locally, keeping the transaction version the toolbox built. Inputs carry the full previous transaction, checked against the input txid and fetched when missing, so the device can verify input amounts. Each input must spend the script its derivation path derives and a `witnessUtxo` it carries must match the previous output, or signing fails with `wallet_ledger_invalid_params` before the device is asked. Zcash transfer signing produces the transparent v5 transaction required by the current Zcash app and accepts v4, v5 and v6 previous transactions, each bound to its planned input.

Ledger Cosmos (ATOM) transfers use the toolbox's own transfer: they pay the toolbox fee for the chosen fee option (Fast by default) instead of a static fee below the Cosmos Hub's minimum gas price, honour `sweep`, and throw when the node rejects the transaction instead of returning its hash.

Cosmos and THORChain signatures are normalised to low-S, THORChain rejects hardened change or address-index path segments instead of silently clearing them, and memo (OP_RETURN) outputs no longer break legacy UTXO signing. The Bitcoin Cash, Litecoin, Dogecoin and Dash apps now sign THORChain swap memos of up to 88 bytes, which used to fail on the device with 0x6a80 from 56 bytes; a longer memo is refused with `wallet_ledger_invalid_params` before the device is asked. THORChain Amino signing keeps a compatibility normaliser for object-shaped deposit assets while signing the canonical string form expected on-chain.

The DMK, its WebHID transport, the context module and the signer kits are bundled into the package, and their licences ship in `dist/THIRD_PARTY_LICENSES.md`.
